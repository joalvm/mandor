Empieza con Request

Mandor Request envía requests HTTP y GraphQL y guarda cada colección como archivos planos en tu disco. Sin cuenta y sin nada que configurar antes.

Tu workspace

La primera vez que se abre, Request crea su carpeta en Documents/Mandor/request/local con un workspace, Personal, y lo abre. No hay nada que elegir.

Un workspace guarda colecciones y entornos. Para otro, abre el menú del workspace en la barra de título, elige Administrar workspaces y luego Nuevo workspace, y ponle un nombre.

Tu primer request

  1. En la barra lateral, + crea una Nueva colección. Su menú añade carpetas y un Nuevo request.
  2. Elige el método, escribe la URL y pulsa Enviar.
  3. La response se abre debajo: arriba su estado, tiempo y tamaño, y luego Body, Headers y Cookies.
  4. Ctrl+S (Cmd+S en macOS) escribe el request en disco. Hasta entonces, el cambio vive solo en su pestaña.

Para una prueba rápida fuera de cualquier colección, el + al final de las pestañas abre un request suelto. Guárdalo y Guardar en… te pide su colección o carpeta; ciérralo sin guardar y desaparece.

Entornos y variables

El selector de entorno está en la barra de título. Crear entorno crea el primero; Administrar entornos los edita todos, con los Globales que comparten todos los entornos.

Escribe una variable como {{nombre}} en la URL, un header, el body o la autenticación. Una que no está definida se envía como texto literal, y el editor indica dónde falta.

Marca una variable como Variable secreta y su valor va al llavero de tu sistema, fuera de la carpeta del workspace: el archivo guarda el nombre con el valor vacío, así que un secreto nunca llega a un commit. Donde el sistema no tiene llavero, el valor vive en memoria hasta que la app se cierra.

Cuando un nombre está definido en varios sitios, gana el más cercano: el script, luego la carpeta, el entorno activo, la colección y los globales.

Los archivos en disco

Cada cosa es un archivo YAML con un id corto por nombre, así que renombrar cambia una línea y no una ruta. Todo salvo .mandor/ está hecho para el commit. 

mandor.yaml
globals.yaml
workspaces/<id>/
  workspace.yaml
  environments/<id>.yaml
  collections/<id>/collection.yaml
  collections/<id>/<id>.yaml        # un request
  collections/<id>/<id>/folder.yaml
  docs/*.md                         # documentación
.mandor/                            # privado: historial, cookies

.mandor/ guarda el historial, las cookies y las pestañas abiertas de este equipo, y git lo ignora.

Compártelo con un origen

La carpeta del workspace es un repositorio git, y Request hace un commit de cada cambio que guardas; nunca escribes un comando de git. Para compartir un workspace o tenerlo en otro equipo, añade un origen: un repositorio vacío al que llegues, por https: o ssh:.

  1. Abre el menú de orígenes, elige Gestionar orígenes y luego Añadir origen.
  2. Dale un nombre y su URL.

Desde entonces, Request trae y envía cambios al abrirse, después de cada guardado, cada minuto y cuando su ventana recibe el foco. Nunca fuerza un push. Cuando el mismo campo cambió en ambos lados, la pestaña Conflictos muestra cada diferencia para resolverla con Usar lo mío o Usar lo entrante.

Scripts

Un script es JavaScript que corre Antes del request o Tras la response, en una colección, una carpeta o un request, en ese orden. Lee y define variables, cambia lo que sale y escribe tests con mandor.test y mandor.expect, cuyos resultados aparecen en la pestaña Tests de la response.

Los scripts corren en un sandbox sin archivos, red ni módulos propios. Uno que llega por un origen o una importación espera hasta que lo apruebes. Para apagarlos todos: Ajustes → Scripts → Correr scripts. Cada objeto y función está en SCRIPTS.md.

Trae lo que ya tienes

Importar un documento, en la barra lateral, lee un archivo OpenAPI 3 o Swagger 2, una colección de Postman v2.1, una exportación de Insomnia, una colección de Bruno o un archivo HAR. En el mismo diálogo puedes pegar un comando curl y Abrir como request.
