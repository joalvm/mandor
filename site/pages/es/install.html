Verificar e instalar

Actualizado el 26 de noviembre de 2026

Las apps aún no llevan certificado de firma de código, así que Windows y macOS preguntan una vez antes del primer arranque. Comprobar antes el archivo te dice que es el que construyó este repositorio, byte por byte.

Elige el archivo

Cada app tiene sus propias versiones, y cada versión trae un instalador por sistema y procesador, con el nombre Mandor-<App>-<versión>-<sistema>. Las descargas muestran las últimas; todas están en GitHub.

Sistema Procesador El nombre termina en
Windows x64 -win-x64.exe
Windows Arm64 -win-arm64.exe
macOS Apple silicon -mac-arm64.dmg
macOS Intel -mac-x64.dmg
Linux x64 -linux-x86_64.AppImage o -linux-amd64.deb
Linux Arm64 -linux-arm64.AppImage o -linux-arm64.deb

Descarga también SHA256SUMS de la misma versión, en la misma carpeta.

Comprueba el checksum

SHA256SUMS lista el SHA-256 de cada archivo de su versión. Un archivo cuyo checksum coincide con su línea es el archivo que guarda la versión, sin cambios en el camino.

Windows, en PowerShell

(Get-FileHash .\Mandor-Request-{{latest.request}}-win-x64.exe -Algorithm SHA256).Hash

Compara lo que imprime con la línea de ese archivo en SHA256SUMS; las mayúsculas no importan.

macOS, en Terminal

shasum -a 256 -c SHA256SUMS --ignore-missing

Linux

sha256sum -c SHA256SUMS --ignore-missing

Córrelo en la carpeta que tiene los dos archivos. Imprime OK junto a cada archivo que encontró y comprobó.

Comprueba dónde se construyó

Cada archivo de una versión lleva una atestación de procedencia: GitHub firma que salió del workflow de releases de joalvm/mandor, en el tag de esa versión. Con la CLI de GitHub instalada: 

gh attestation verify Mandor-Request-{{latest.request}}-win-x64.exe --repo joalvm/mandor

Solo pasa con un archivo construido por ese workflow. Un archivo cambiado después del build, o construido en otro lugar, falla.

Ábrelo en Windows

  1. Ejecuta el instalador.
  2. SmartScreen dice Windows protegió su PC. Elige Más información.
  3. Elige Ejecutar de todas formas. Windows pregunta una vez por archivo.

Con Control inteligente de aplicaciones activado, Windows no ejecuta en absoluto una app sin certificado.

Ábrelo en macOS

  1. Abre la imagen de disco y arrastra la app a Aplicaciones.
  2. Abre la app. macOS rechaza el primer arranque.
  3. Abre Configuración del Sistema → Privacidad y seguridad, busca el mensaje sobre la app en Seguridad y elige Abrir igualmente.
  4. Confirma. macOS pregunta una vez.

Las apps van firmadas ad hoc, sin certificado de desarrollador de Apple: el checksum y la atestación son cómo sabes de dónde vienen.

Instálalo en Linux

AppImage

chmod +x Mandor-Request-{{latest.request}}-linux-x86_64.AppImage
./Mandor-Request-{{latest.request}}-linux-x86_64.AppImage

Un AppImage necesita FUSE 2. En Ubuntu 22.04 viene con libfuse2; en 24.04, con libfuse2t64.

Paquete Debian

sudo apt install ./Mandor-Request-{{latest.request}}-linux-amd64.deb

Actualizaciones

Ajustes → Actualizaciones elige cómo llegan. Automático, el modo por defecto, busca al abrir la app y cada seis horas, y descarga lo que encuentra. Avisar busca y espera tu orden para descargar. Manual solo busca cuando lo pides. Ninguno reinicia la app solo.

Buscar es un request a GitHub por los archivos de actualización de tu canal: GitHub ve tu dirección IP y la versión de la app, como en cualquier request, y nada de tu trabajo va con él. El canal elige entre versiones estables y betas; una instalación de una beta sigue las betas hasta que eliges Estable.

En Windows y desde el AppImage, la app se actualiza sola. En macOS y desde el paquete Debian, te avisa de la versión nueva y abre la página para descargarla.
