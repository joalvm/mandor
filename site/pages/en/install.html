Verify and install

Updated 26 November 2026

The apps carry no code-signing certificate yet, so Windows and macOS ask once before the first launch. Checking the file first tells you it is the one this repository built, byte for byte.

Pick the file

Each app has its own releases, and each release holds one installer per system and processor, named Mandor-<App>-<version>-<system>. The downloads list the latest ones; every release is on GitHub.

System Processor The name ends in
Windows x64 -win-x64.exe
Windows Arm64 -win-arm64.exe
macOS Apple silicon -mac-arm64.dmg
macOS Intel -mac-x64.dmg
Linux x64 -linux-x86_64.AppImage or -linux-amd64.deb
Linux Arm64 -linux-arm64.AppImage or -linux-arm64.deb

Download SHA256SUMS from the same release too, into the same folder.

Check the checksum

SHA256SUMS lists the SHA-256 of every file in its release. A file whose checksum matches its line is the file the release holds, unchanged on the way.

Windows, in PowerShell

(Get-FileHash .\Mandor-Request-{{latest.request}}-win-x64.exe -Algorithm SHA256).Hash

Compare what it prints with the line of that file in SHA256SUMS; capitals do not matter.

macOS, in Terminal

shasum -a 256 -c SHA256SUMS --ignore-missing

Linux

sha256sum -c SHA256SUMS --ignore-missing

Run either in the folder that holds both files. It prints OK next to each file it found and checked.

Check where it was built

Every file of a release carries a provenance attestation: GitHub signs that it came out of the release workflow of joalvm/mandor, at that release's tag. With the GitHub CLI installed: 

gh attestation verify Mandor-Request-{{latest.request}}-win-x64.exe --repo joalvm/mandor

It succeeds only for a file built by that workflow. A file changed after the build, or built anywhere else, fails.

Open it on Windows

  1. Run the installer.
  2. SmartScreen says Windows protected your PC. Choose More info.
  3. Choose Run anyway. Windows asks once per file.

With Smart App Control on, Windows does not run an app without a certificate at all.

Open it on macOS

  1. Open the disk image and drag the app to Applications.
  2. Open the app. macOS refuses the first launch.
  3. Open System Settings → Privacy & Security, find the message about the app under Security and choose Open Anyway.
  4. Confirm. macOS asks once.

The apps are signed ad hoc, without an Apple developer certificate: the checksum and the attestation are how you know where they come from.

Install it on Linux

AppImage

chmod +x Mandor-Request-{{latest.request}}-linux-x86_64.AppImage
./Mandor-Request-{{latest.request}}-linux-x86_64.AppImage

An AppImage needs FUSE 2. On Ubuntu 22.04 it comes with libfuse2, on 24.04 with libfuse2t64.

Debian package

sudo apt install ./Mandor-Request-{{latest.request}}-linux-amd64.deb

Updates

Settings → Updates chooses how they arrive. Automatic, the default, looks when the app opens and every six hours, and downloads what it finds. Notify looks and waits for you to download. Manual only looks when you ask. None of them restarts the app by itself.

Looking is one request to GitHub for the update files of your channel: GitHub sees your IP address and the version of the app, as with any request, and nothing of your work goes with it. The channel picks between stable versions and betas; an install of a beta follows the betas until you pick Stable.

On Windows and from the AppImage, the app updates itself. On macOS and from the Debian package, it tells you of the new version and opens the page to download it.
