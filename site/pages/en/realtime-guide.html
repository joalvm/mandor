Get started with Realtime

Mandor Realtime opens WebSocket and Socket.IO connections, logs every message both ways and keeps its workspace as plain files on your disk. No account, nothing to set up first.

Your workspace

The first time it opens, Realtime creates its folder in Documents/Mandor/realtime/local with one workspace, Personal, and opens it. There is nothing to pick.

A workspace holds connections, saved messages and environments. For another one, open the workspace menu in the title bar, choose Manage workspaces, then New workspace, and give it a name.

Your first connection

  1. In the sidebar, the + of Connections makes a New connection, with its URL still empty.
  2. Type the address in Connection URL. A WebSocket server takes ws: or wss:; a Socket.IO server takes http: or https:.
  3. For Socket.IO, open the connection's menu, choose Settings and set its Transport: version 2, or 3 and 4.
  4. Press Connect. Disconnect closes it again.

Send and read

Write the payload in the Message tab of the composer and press Send, or Ctrl+Enter. On Socket.IO the composer also names the Event, and Wait for ack holds the message open until the server answers it.

Activity logs what you send and everything that arrives, each event as its own row, with no listener to set up first. Search it, filter it, export it or clear it from its bar.

Saved messages

A message you send often belongs in a collection. The menu of a collection or a folder adds a New message. Opening one loads it into the composer of the open connection, ready to send; Ctrl+S writes your change back to it.

Environments and variables

The environment picker sits in the title bar, and the address bar of a connection shows which one it uses. Create environment makes the first one; Manage environments edits them all, with the Globals every environment shares.

Write a variable as {{name}} in the URL or a message. One that is not defined is sent as the literal text.

Mark a variable as Secret variable and its value goes to the keychain of your system, outside the workspace folder: the file keeps the name with an empty value, so a secret never reaches a commit. Where the system has no keychain, the value lives in memory until the app closes.

The files on disk

Each thing is a YAML file named by a short id, so a rename changes one line and not a path. Everything but .mandor/ is meant to be committed. 

mandor.yaml
globals.yaml
workspaces/<id>/
  workspace.yaml
  connections/<id>.yaml              # a connection
  environments/<id>.yaml
  collections/<id>/collection.yaml
  collections/<id>/<id>.yaml        # a saved message
  collections/<id>/<id>/folder.yaml
  docs/*.md                         # documentation
.mandor/                            # private to this computer

.mandor/ holds what belongs to this computer alone, such as the open tabs, and it is ignored by git.

Share it through an origin

The workspace folder is a git repository, and Realtime commits each change you save on its own; you never type a git command. To share a workspace or keep it on another computer, add an origin: an empty repository you can reach, by https: or ssh:.

  1. Open the origin menu, choose Manage origins, then Add origins.
  2. Give it a name and its URL.

From then on, Realtime brings in and sends changes when it opens, after each save, every minute and when its window gets focus. It never forces a push. When the same field changed on both sides, the Conflicts tab shows each difference to settle with Use mine or Use the incoming.

Scripts

A connection runs JavaScript at three moments: Before connecting, On connect and On messages. Write them in the Scripts part of the connection's settings. A script reads and sets variables, sends with mandor.socket.send and reads what arrived from mandor.message.

Scripts run in a sandbox with no files, network or modules of their own. One that arrives through an origin or an import waits until you approve it. To turn them all off: Settings → Scripts → Run scripts. Every object and function is in SCRIPTS.md.

Bring what you have

Import a document reads an AsyncAPI 2 or 3 file. Import a workspace brings in one exported from Mandor. A workspace can also be exported as AsyncAPI 3.
