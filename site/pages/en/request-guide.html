Get started with Request

Mandor Request sends HTTP and GraphQL requests and keeps every collection as plain files on your disk. No account, nothing to set up first.

Your workspace

The first time it opens, Request creates its folder in Documents/Mandor/request/local with one workspace, Personal, and opens it. There is nothing to pick.

A workspace holds collections and environments. For another one, open the workspace menu in the title bar, choose Manage workspaces, then New workspace, and give it a name.

Your first request

  1. In the sidebar, + makes a New collection. Its menu adds folders and a New request.
  2. Pick the method, type the URL and press Send.
  3. The response opens below it: its status, time and size on top, then Body, Headers and Cookies.
  4. Ctrl+S (Cmd+S on macOS) writes the request to disk. Until then, the change lives only in its tab.

For a quick try outside any collection, the + at the end of the tabs opens a loose request. Save it and Save to… asks for its collection or folder; close it unsaved and it is gone.

Environments and variables

The environment picker sits in the title bar. Create environment makes the first one; Manage environments edits them all, with the Globals every environment shares.

Write a variable as {{name}} in the URL, a header, the body or the auth. One that is not defined is sent as the literal text, and the editor says where it is missing.

Mark a variable as Secret variable and its value goes to the keychain of your system, outside the workspace folder: the file keeps the name with an empty value, so a secret never reaches a commit. Where the system has no keychain, the value lives in memory until the app closes.

When one name is set in several places, the closest wins: the script, then the folder, the active environment, the collection and the globals.

The files on disk

Each thing is a YAML file named by a short id, so a rename changes one line and not a path. Everything but .mandor/ is meant to be committed. 

mandor.yaml
globals.yaml
workspaces/<id>/
  workspace.yaml
  environments/<id>.yaml
  collections/<id>/collection.yaml
  collections/<id>/<id>.yaml        # a request
  collections/<id>/<id>/folder.yaml
  docs/*.md                         # documentation
.mandor/                            # private: history, cookies

.mandor/ holds the history, the cookies and the open tabs of this computer, and it is ignored by git.

Share it through an origin

The workspace folder is a git repository, and Request commits each change you save on its own; you never type a git command. To share a workspace or keep it on another computer, add an origin: an empty repository you can reach, by https: or ssh:.

  1. Open the origin menu, choose Manage origins, then Add origins.
  2. Give it a name and its URL.

From then on, Request brings in and sends changes when it opens, after each save, every minute and when its window gets focus. It never forces a push. When the same field changed on both sides, the Conflicts tab shows each difference to settle with Use mine or Use the incoming.

Scripts

A script is JavaScript that runs Before the request or After the response, on a collection, a folder or a request, in that order. It reads and sets variables, changes what goes out and writes tests with mandor.test and mandor.expect, whose results show in the Tests tab of the response.

Scripts run in a sandbox with no files, network or modules of their own. One that arrives through an origin or an import waits until you approve it. To turn them all off: Settings → Scripts → Run scripts. Every object and function is in SCRIPTS.md.

Bring what you have

Import a document, in the sidebar, reads an OpenAPI 3 or Swagger 2 file, a Postman v2.1 collection, an Insomnia export, a Bruno collection or a HAR file. In the same dialog you can paste a curl command and Open as request.

Keys

On macOS, Cmd takes the place of Ctrl.

Command palette Ctrl+Shift+P
Send Ctrl+Enter
Save Ctrl+S
Search the workspace Ctrl+Shift+F
Settings Ctrl+,
