Security

A summary of the security policy. The full one is SECURITY.md, in the repository.

Report a vulnerability

Report it privately, never in a public issue: open a private report on GitHub. Only the author sees it.

Useful to include:

  • which app, its version and your operating system;
  • what an attacker can do, and what they need first: a crafted file, a malicious server, local access;
  • the steps to reproduce it, or a proof of concept.

You get an answer within seven days. Once a fix is out, the advisory is published with credit to you, unless you prefer otherwise.

Supported versions

The latest release of each app receives security fixes. An older one does not: update to the latest to get them.

What matters most

Both apps run locally, without an account or a server of their own. Above all:

  • anything that lets a document, a collection or a server response run code or reach the filesystem;
  • secrets leaving the secure storage of the system, or landing in your files or logs;
  • a transport reaching a kind of address it should refuse.

Scripts

Requests, folders, collections and connections can carry scripts, and their author may be a stranger. Two promises hold without exception: a value marked secret never reaches a script, and no malicious code runs on your machine because of Mandor.

  • A script nobody approved on your machine does not run. Opening, importing or syncing never runs one, and a text that changes asks again.
  • Scripts run in QuickJS compiled to WebAssembly, with limits on time, memory, output and network calls, and see nothing of the app around them.
  • Settings → Scripts → Run scripts stops every script at once, without deleting any or undoing an approval.

What is left, and how to write scripts: SECURITY.md and SCRIPTS.md.
